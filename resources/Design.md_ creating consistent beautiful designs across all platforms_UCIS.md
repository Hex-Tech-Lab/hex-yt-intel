**Answer Deep Dive**:

4. **Identify & Load Skills** (10 min)
   - Open design.md or New Form library
   - List 2–3 skills you want to apply (e.g., "laser," "skumorphic buttons," "color gradient")
   - Copy skill prompts into a separate file
   - Example: Laser skill = "[Include WebGL animation of laser beams sweeping across hero section at 60fps. Use primary color. Triggered on page load.]"

5. **Set Up Agent Context** (10 min)
   - Open your AI agent (Claude, Aura, Cursor)
   - Create new project/conversation for your product
   - In system prompt or first message, paste:
     - Full design.md (markdown content)
     - 2–3 skill prompts (as bullet points)
     - Product brief (1–2 sentences: category, target user, primary CTA)

6. **First-Pass Generation: Baseline Landing Page** (15 min)
   - Prompt: "Using the attached design.md system and the [laser/3D] skill, create a landing page for [product name], a [category]. Include [hero section, features list, pricing, CTA]. Make it beautiful and on-brand. Enforce design.md rules: use [primary color] for buttons, [secondary font] for headings, [spacing unit] for padding."
   - Agent generates HTML/React component
   - Review output; take screenshot of design direction

7. **Remix Phase: Rapid Variation Exploration** (30 min)
   - Generate 5–6 variations by tweaking prompts:
     - Variation 1: "Add laser effect to hero"
     - Variation 2: "Swap primary color to [alt color]; keep laser"
     - Variation 3: "Use skumorphic buttons instead of flat"
     - Variation 4: "Change layout to 3-column grid instead of 2-column"
     - Variation 5: "Add 3D globe animation to hero"
   - View side-by-side; note which feels right
   - Vote on direction (visual preference, not overthinking)

8. **Iterate Phase: Taste Refinement** (1–2 hours per session, multiple sessions)
   - Once direction locked, switch to iterate mode
   - Make 10–20 small refinements per session:
     - "The primary button's padding feels too tight; increase by 4px"
     - "The laser animation is too fast; slow to 3 sec duration"
     - "Hero text color is too dark; should be [specific hex]"
     - "Add more breathing room between sections; increase margin to 48px"
   - Each iteration tests one hypothesis (does this make it better?)
   - Track which iterations feel good; document decision rationale

9. **Cross-Medium Remix: Mobile, Slide, Motion** (30 min per medium, optional)
   - Once web design feels locked, remix to mobile: "Convert this design to mobile (320px viewport), keeping design.md rules. Stack sections vertically."
   - Remix to slide deck: "Turn this landing page into a 5-slide pitch deck using design.md colors and typography."
   - Remix to motion video: "Create a 30-sec promo video showcasing [product], using design.md system and laser effect."

10. **Export & Documentation** (15 min)
    - Export final HTML/React component
    - Document your design decisions: which skills were used, which colors were final, what iterations worked
    - Save design.md + vocabulary doc + final design as reference for future projects

**Success Metrics**:
- Design is visually cohesive across all sections (no abrupt style shifts)
- Color, typography, spacing are consistent across mediums (web, mobile, slide, video)
- Animation/effects enhance rather than distract
- Non-designers reviewing output can't immediately identify it as AI-generated
- You can describe design system in <5 sentences (sign of internalizing the rules)

**Common Pitfalls** (with timestamps):
1. **Only downloading HTML, not design.md** (22:03): Design.md is the system; HTML is implementation. Without design.md, agent has no "memory."
2. **One-shot design expectation** (13:55-15:24): Expecting beautiful output on first prompt. Reality: 20+ iterations per design. Budget time.
3. **Not iterating; sticking with Remix** (39:10-39:39): Remix finds direction; Iterate develops taste. If you skip Iterate, output feels surface-level.
4. **Changing design.md mid-project** (11:32): System rules are your constraint; if you keep shifting rules, agent gets confused. Lock system early.
5. **Not learning design.md vocabulary** (33:19-34:08): If you don't understand "font-smoothing," "secondary color," "spacing rhythm," you can't direct agent effectively.

**Troubleshooting Guide**:
- **Problem**: Design drift across sections (hero is beautiful, features section is generic).
  **Solution**: Add explicit constraint to each prompt: "Use design.md rules: [primary color] for CTA, [heading font] for section titles, [spacing unit] for padding."
- **Problem**: Agent generates layout that doesn't match design.md system.
  **Solution**: Provide HTML as reference (agent can see structural patterns). Also, be more explicit in prompt: "Follow this layout pattern from the HTML file."
- **Problem**: Colors are off; don't match design.md.
  **Solution**: Copy exact hex codes from design.md vocabulary. Use hex codes, not color names ("use #FF5733, not 'red'").
- **Problem**: Animation is choppy or looks generated.
  **Solution**: Slow animation down (increase duration). Or replace with simpler effect (fade instead of laser, if laser feels glitchy).
- **Problem**: Feels like I'm still not iterating enough; design doesn't feel "soul-ful."
  **Solution**: Commit to 50+ iterations minimum. Taste develops through volume. Each iteration should test one micro-decision (color, spacing, animation timing, or copy tweak).

**Risk Factors**:
- **Token Overflow**: Design.md + HTML can consume 2K–4K tokens. If using token-limited API, will quickly hit limits. *Mitigation*: Use context windows strategically; compress design.md if needed (summarize non-critical sections).
- **Design Homogeneity**: If you and 10 other founders download same design.md, output will resemble each other. *Mitigation*: Invest iteration depth (1,000+ iterations → unique taste signals emerge).
- **Tool Lock-in**: Design.md is portable, but some AI agents may not support markdown attachments well. *Mitigation*: Test agent with simple design.md first; have fallback tool ready.
- **Over-reliance on AI**: If you let AI make all decisions, output loses soul. *Mitigation*: Humans make taste decisions; AI executes. You decide direction; agent refines.

### **System 2: The Taste Curation & Design Memory Development Workflow**

*Source Section*: 47:22–50:16, 48:59–49:56

*Difficulty Level*: Beginner (no design experience; pure curation)

*Time Investment*: 30 min weekly (ongoing discipline)

*Prerequisite Knowledge*: Ability to critique design (subjective; no expertise required)

*Prerequisites Required*:
- Tool for collecting inspiration (Figma, Notion, Pinterest, Miro, or custom browser extension)
- Access to 10–20 apps in your product category
- 1–2 hours for initial research phase

**Step-by-Step Implementation**:

1. **Define Niche & Create Taste Categories** (30 min)
   - Choose narrow niche: "fitness SaaS" not "SaaS"; "creator tools" not "tools"
   - Identify taste dimensions relevant to your category:
     - **Motion**: How do transitions/animations feel? (snappy, slow, bouncy, subtle)
     - **Color**: Palette vibrancy? (vibrant, muted, monochrome, gradient-heavy)
     - **Typography**: Sophistication level? (playful, corporate, editorial, technical)
     - **Interaction**: Button feedback? (satisfying clicks, smooth hover states, delight moments)
     - **Layout**: Information density? (spacious, dense, balanced, minimalist)
   - Create one category per dimension.

2. **Research & Audit Competitors** (1–2 hours)
   - List 15–20 apps/products in your niche (include: direct competitors, adjacent products, inspiration sources)
   - Use each for 10–15 min; focus on first-impression moments:
     - Hero section design
     - Color & typography choices
     - Animated transitions
     - Button/form interactions
     - Overall "feel" (playful? serious? premium? scrappy?)
   - Screenshot 3–5 moments you like from each

3. **Organize Screenshots by Taste Dimension** (30 min)
   - Create a "Taste Board" in Figma, Notion, or Pinterest:
     - **Motion** section: screenshots of animations you like (tag by type: reveal, scroll trigger, hover, load)
     - **Color** section: screenshots of palettes you like (tag by feel: vibrant, muted, luxury, energetic)
     - **Typography** section: screenshots of type systems (tag by vibe: editorial, technical, playful)
     - **Interaction** section: screenshots of button states, form feedback
     - **Layout** section: screenshots of information architecture patterns
   - Goal: Create visual thesaurus of taste options

4. **Tag & Label Patterns** (15 min)
   - For each screenshot, add tags:
     - Emotional vibe: "energetic," "serious," "playful," "premium"
     - Technique: "gradient," "solid color," "serif font," "sans-serif," "smooth scroll," "snappy transition"
     - Category fit: "fitness," "finance," "creator," "health"
     - Personal rating: ⭐⭐⭐ (1–5 stars) for how much you love it
   - Example: Fitness app hero animation tagged: ["energetic," "smooth scroll," "gradient background," "fitness," "⭐⭐⭐⭐⭐"]

5. **Review Routine: Weekly Taste Audit** (20 min weekly)
   - Every Monday or before starting a new design project, spend 20 min reviewing Taste Board
   - Do a quick scan: which taste dimensions are trending in your niche? (e.g., "all fitness apps are using darker color schemes now")
   - Ask: "Which of these feels authentic to my product? Which feels like me?"
   - Identify 2–3 taste vectors you want to integrate into your next design

6. **Translate Taste to Design.md Vocabulary** (10 min per design session)
   - Before prompting agent, translate taste observations to design vocabulary:
     - **Observation**: "I love how [competitor] uses a smooth, slow scroll animation on their hero"
     - **Translation to design.md**: "Use easing function: cubic-bezier(0.33, 0.66, 0.66, 1); animation duration: 2s; trigger: onScroll"
     - **Prompt to agent**: "Add smooth scroll reveal animation (2s duration, easing [cubic-bezier...]) to hero section"
   - This bridges subjective taste (what you see) and executable design (what you tell agent)

7. **Iterate on Taste Signals** (10 min per iteration)
   - After agent generates design, compare to Taste Board
   - Ask: "Does this feel like my taste? What's off?"
   - If off, look back at Taste Board for reference:
     - "I want [this color palette] from [competitor], not [current color]"
     - "I want [this animation feel] from [competitor], not [current animation]"
   - Prompt agent with specific feedback: "The motion feels too bouncy; use the cubic-bezier easing from [design reference]"
   - Iterate 10+ times to align with taste signals

8. **Update Taste Board Quarterly** (1 hour per quarter)
   - Every 3 months, re-audit competitors. Taste evolves; tools & trends shift.
   - Add new categories if needed (e.g., "emerging trends," "what we're not doing")
   - Remove outdated inspiration; add new finds
   - Identify patterns: are all great products in your niche now using [specific color/motion/layout]?

**Success Metrics**:
- You can describe your taste in 5–10 words ("fast animations, bold colors, minimal text, premium typography")
- Your designs are consistently different from competitors (not cookie-cutter)
- When comparing your design to others, you can articulate why yours feels better (specific taste vectors)
- Your agent takes feedback more effectively because you're speaking in design language, not vague critique
- You're making faster, more confident design direction decisions (less remix cycles, more iterate cycles)

**Common Pitfalls**:
1. **Passive collection without critique** (48:59-49:29): Saving designs without analyzing why you like them. *Fix*: For each screenshot, write 1-sentence observation: "I like this because the animation is slow and deliberate."
2. **Copying instead of learning** (47:03-47:53): Using Taste Board as template library. *Fix*: Taste Board teaches system/principles, not specific designs. Apply principles to your own design.
3. **Ignoring category specificity** (47:22-47:53): Mixing taste from unrelated categories (e.g., fitness + fintech). *Fix*: Keep separate taste boards per niche. Taste is category-specific.
4. **Not iterating on taste signals** (30:22-31:30): Generating one design and stopping. Taste develops through iteration. *Fix*: Generate → Compare to Taste Board → Identify gaps → Iterate 20+ times.
5. **Static taste board** (quarterly refresh skipped): Taste evolves; if board is stale, taste signals become irrelevant. *Fix*: Monthly or quarterly review.

**Troubleshooting Guide**:
- **Problem**: I have a Taste Board but I'm not using it during design.
  **Solution**: Create a "pre-design ritual": spend 10 min reviewing Taste Board before first prompt. Note 2–3 taste vectors you want. Screenshot them. Reference during iteration.
- **Problem**: My taste signals are too vague ("I like the energy of this design"). Agent doesn't understand.
  **Solution**: Translate taste to design vocabulary: "The energy comes from: (1) fast animation (0.5s duration), (2) vibrant color (#FF5733), (3) bold typography (800 weight)." Agent now understands what "energy" means.
- **Problem**: I'm collecting designs but not seeing patterns.
  **Solution**: Tag aggressively. Create reports: "How many designs use motion? How many use bold color?" Patterns emerge.
- **Problem**: My Taste Board is 100+ designs; it's overwhelming.
  **Solution**: Keep only 20–30 designs. Quality over quantity. Each design should be a clear example of a specific taste vector.

**Risk Factors**:
- **Trend-Chasing Risk**: If you only follow current trends, your taste becomes dated within 6 months. *Mitigation*: Include timeless designs (from 5 years ago) in Taste Board alongside current designs. Identify what's perennial vs. trendy.
- **Audience Mismatch Risk**: Your taste may not match user preferences. *Mitigation*: Validate with users. Show 2–3 design directions to target users; let them vote. Adjust taste signals based on feedback.
- **Over-Customization Risk**: If you iterate too much based on taste, you may diverge too far from design.md system (losing consistency). *Mitigation*: Keep design.md system as anchor. Taste signals adjust within system bounds, not against them.
