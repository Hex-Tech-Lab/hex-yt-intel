### 3. Chat stuck on "analysis is still being generated" / "no transcript" for completed analyses
- **Plan**: Deep RCA — user explicitly asked "focus on this deeply... think step by step," suspecting a pipeline/contract mismatch.
- **RCA (root cause, confirmed by code read, not guess)**:
  - Synthesis Console loads analysis via `GET /api/analyses/[id]`, which calls `safeReconstructMarkdown()` — falls back to rebuilding markdown from `analysis_payload` when the `analysis_markdown` column is empty/stale.
  - Chat grounding loads the **same row** via `SupabaseAnalysisAdapter.getAnalysisGrounding()`, which read **only** the raw `analysis_markdown` column — no `analysis_payload` fallback, and didn't even `select` that column.
  - Net effect: an analysis whose `analysis_markdown` column lagged behind (chunked/stitched persistence, `web/app/api/analyses/persist/route.ts`) rendered perfectly in the Console (reconstructed) but was **empty** to chat → grounding gate correctly refused, but on a false premise ("no transcript") since content did exist in `analysis_payload`.
  - Secondary symptom (description missing) had the identical shape: `description` was read only from `validation_report.metadata.description`, never from `analysis_payload.metadata.description`.
- **Fix**: `getAnalysisGrounding()` now selects `analysis_payload`, applies the **same** `reconstructMarkdown()` fallback logic as the Console route (size-capped at 100KB, same as `/api/analyses/[id]`), and falls back to `analysis_payload.metadata.description` when `validation_report` never captured it.
- **Done**: Code committed, `tsc --noEmit` clean on the changed file.
- **Verified**: **Not yet** — needs a live chat re-test on an analysis previously exhibiting the refusal, post-deploy.
- **Proof**: Commit `4f8b4228`. **Action: confirm on next live test** — ask "what was said around min. 52?" and "do you have the description?" on the same video that failed before.
