## Refuted

| PR | Candidate (what a less careful audit would flag) | Why refuted (evidence) |
|---|---|---|
| 438 | Budget-refusal path (`analysis.ts:1574-1579`) sends an error frame then `controller.close()`, seemingly killing the whole multi-bundle analysis on one refused cell | Each stream bundle is a separate SSE stream opened per-bundle by the client (`web/hooks/useSSEStream.ts:775-815` — `attemptBundle` → one `SynthesisStreamAdapter` per bundle, one retry, then `handleStreamError` for that bundle only). The refusal fires before any LLM call (comment at `analysis.ts:1570-1573`), so the retry is free; remaining bundles continue. Matches the documented cell-failure semantics — no whole-run kill. |
| 438 | Cascade registry validation allowlist living in code (`web/lib/config/cascade-validation.ts`) instead of the DB could drift from registry values | Anti-drift is the design intent: the allowlist is *derived from* `CASCADE_FALLBACKS` in the same code that writes the registry keys, and the migration tags `cascade.%` rows with a `validation.kind = "cascadeRegistry"` marker so the admin save path dispatches to the code-derived Zod validator. A DB-side allowlist would be the drift risk, not the fix. Fail-closed on unknown models is correct behavior. |
| 438 | `validate` webhook could still ghost-ack on embedding failure | Fixed in this very PR: publish failure is fail-closed 503 so QStash redelivers (test at `worker/src/__tests__/webhooks-validate.test.ts` per diff: "embedding publish failure is fail-closed: 503 … never a ghost 200"). This remediates the 10X-scan V23-family finding. |
| 439 | `DeepgramNova2Adapter` fetching a fixed external URL could be SSRF-reachable / response buffered unboundedly (V10 shape) | URL is the constant `https://api.deepgram.com/v1/listen` (no user influence), request body is server-fetched transcript audio, and the adapter enforces a 10 s fail-closed timeout with typed `DeepgramDiarizationError`. No user-influenced URL, no unbounded buffering. |
| 436 | `JevTextParser` could fabricate default scores when the JEV Decisions API call fails/malforms (fail-open on the S1–S6 evidence layer) | Verified the opposite: the parser throws on failed/malformed calls — never returns fabricated defaults. Fail-closed contract as designed. |
| 437 | Bake-off harness mocks diarization/A-V sensors to match each video's hand label, so sensor-agreement metrics are partly fabricated — looks like a rigged eval | The file header self-declares the mock; ground truth is the human hand-label file (`S1_S6_POOL_GROUND_TRUTH.json`, deliberately not in repo), and the harness exists to measure the *router* against labels, not sensor accuracy. Documented limitation, not a defect. Tangent note only. |
| 432 | `timedFetch` wrapper (90 s on worker `/fetch-transcript`, plus OpenRouter calls) could swallow timeouts and retry unboundedly | Wrapper surfaces timeouts as rejections to the existing single-attempt call sites; no retry loop added in the diff. Hardening only. |
| 441 | `GroundedExtractionEngine` JSON-parse now logs `console.warn` with raw output — possible secret/PII leakage to logs | The warn payload is `parseError` (the parser error object), not `rawText`; the raw output travels only in the thrown `GroundedExtractionError` for Sentry capture, which is the existing convention. No leak introduced. |
