Blast radius is bounded to the attacker's own analysis (quota bouncer still gates analysis count) — hence P2, not P1. The JevFallbackBudget.ts header itself flags this ("A tampered inline plan could inflate costCapCents … binding the plan into the stream token is tracked debt"), but the debt is untracked anywhere user-visible. | Bind a hash of the plan into the v2 stream token (worker already verifies `verifyStreamToken` there), OR ignore `costCapCents`/`fullTranscriptCallCents`/`estimateCents` from the inline path and re-resolve the cap from the Settings Registry server-side in the worker (S2S-fetched plans keep their HMAC-verified fields).
