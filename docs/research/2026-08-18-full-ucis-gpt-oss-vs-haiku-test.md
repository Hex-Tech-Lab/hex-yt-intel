# Full UCIS 11-Dimension (5-Bundle-Stream) GPT-OSS-120B vs Haiku 4.5 Test

**Date**: 2026-08-18
**Status**: BLOCKED after architecture trace + candidate-row selection — real, reproducible data-availability gap found before any model comparison could be run. Reporting honest partial progress per task instructions, not fabricating scores.

## 1. Architecture trace (real, verified against source)

The 11 UCIS dimensions are NOT generated by a single call (unlike the Dimension-0 digest tested earlier tonight). The client (`web/hooks/useSSEStream.ts`) fires 5 parallel `POST /analyze-llm-stream` requests to the Cloudflare Worker (`worker/src/routes/analysis.ts`), each carrying a different `dimensions: number[]` subset and `chunkIndex`/`totalChunks`. The default bundle split (`web/lib/adapters/settings-adapter.ts:170`, `getDefaultAdminSettings`) is:

| Bundle | Dimensions | Notes |
|---|---|---|
| 1 | [1] | Apex Intelligence — largest, carries `persona` extra field |
| 2 | [8] | Semantic/Knowledge Graph — carries `knowledgeGraph` extra field (max 15 nodes/20 edges) |
| 3 | [2, 4, 6] | Provenance, Psychological, Comparative |
| 4 | [5, 7, 10] | Core Intelligence, Implementation Systems, Credibility |
| 5 | [3, 9, 11] | Architecture, Forward Intelligence, Monetization (+`classification`/`monetizationVerdict`) |

Each bundle call independently builds its prompt via `PromptBuilder.build()` (`worker/src/services/PromptBuilder.ts`): the full `UCIS_V5_3_SYSTEM` base template (`web/lib/prompts/ucis-v5.3.ts`) plus metadata/persona/transcript injection (`getUCISPrompt`, `web/lib/prompts/factory.ts`) plus a segment-specific suffix restricting output to only that bundle's dimension(s), 400-word cap per dimension, explicit extra-field instructions, and the Insufficient Data Protocol fallback. Each bundle runs its own independent `LLMCascade` (same registry-resolved cascade, same model per tier) and persists independently via `PersistService`/`ADR 021 Phase 1` merge logic. Confirmed: Dimension 7 (Implementation Systems) is bundled with 5 and 10, not isolated; Dimension 8 (Knowledge Graph) is its own single-dimension bundle, and Dimension 1 (Apex) is also its own single-dimension bundle — these two get the most output budget per call.

## 3. Blocker found (real, verified — not assumed)

Regenerating the same 5-bundle-stream calls requires the SAME real transcript each historical row was analyzed against. Checked:

- `transcripts` table (ADR 012's 72h compliance-retention tier, holding `content`/`segments`/`language` keyed by `video_id`): **0 rows in the entire table** (`select count(*) from transcripts` → 0). All 8 candidate rows are 4-10 weeks old — far past the 72h TTL — so their original transcript text/segments are gone from the DB, by design (compliance retention, not a bug).
- Checked for any CURRENT (last 72h) `dimension_count = 11` rows that would still have a live transcript: **zero rows**. The 10 most recent `analyses` rows (back to 2026-08-06) all have `dimension_count = null` — none are full 11-dimension UCIS analyses in this window at all (mix of `edge-stream` and `Claude Haiku 4.5 (Vertex)` model_used values, a different label pattern worth a separate follow-up note: "(Vertex)" suggests a routing path not reflected in this doc's model-tracking assumptions).

Net effect: there is no historical row where both (a) `model_used`/`model_attempted` are independently confirmed Haiku 4.5, (b) `dimension_count = 11`, and (c) the real source transcript is still retrievable from the DB. Re-running the exact same prompts against the exact same input (the task's explicit requirement — "same real prompts... same real transcript input") is not possible from stored data alone for any of the 8 candidates found.

Not attempted as a workaround within this pass: re-fetching the transcript fresh from YouTube for these specific video IDs (captions are usually static, so a fresh fetch would likely match the original closely, but not provably identically — and doing so for 8-12 rows x 5 bundles was already the token-budget-risk flagged in the task brief before this blocker was even hit). Stopping here rather than substituting a not-provably-equivalent transcript and calling the resulting comparison "real."
