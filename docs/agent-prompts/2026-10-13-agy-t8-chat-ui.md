## 1. Context & Problem Statement

The chat dock lives in `web/components/templates/console/ChatDock.tsx` (plus related chat message/bubble components it imports). Five UI defects, from owner UAT on `https://uat.getvintel.com`:

1. Timestamps inside chat answers render in a different blue from the timestamps in the right-hand flyout panel. They must use the same blue token as the flyout.
2. Markdown tables in chat replies do not span the full message width. They must span the full width of the message container.
3. A thin divider line sits between the message list and the input box. Remove it.
4. Text selected inside the user's own message bubble has no visible highlight. The user bubble uses the accent colour as background, so the default selection colour is invisible. Give selected text in user bubbles a visible selection highlight.
5. Double-clicking the user's own bubble causes a 214 ms INP. The handler lives on the `astryx-chat-message-bubble.user` element (find it via the graph). Stop it blocking the main thread. Do not just delete behaviour the user relies on; if the handler does work synchronously on double-click, defer or make it cheap, and say what it did.

## 2. Contract & Implementation Directives

- Scope is exactly the five items above. Anything else you notice is a tangent: report it under "Tangents found", do not fix it.
- Keep the diff surgical: no drive-by formatting, no unrelated refactors.
- Use Tailwind / Astryx tokens already in the codebase. Do not introduce shadcn/ui. Do not add a new dependency.
- For item 1, the colour must come from the same token or class the flyout timestamps use. Show the token name in the report.
- For item 4, use a `::selection` (or equivalent) rule scoped to the user bubble with a contrasting highlight colour that passes WCAG 2.1 AA contrast against the bubble background.
- For item 5, report the measured cause (what the handler does) and the before/after reasoning. Do not claim an INP number you did not measure.
- Each item needs a regression test where a unit or component test is feasible. If a visual-only item cannot be unit-tested, say so explicitly and give the manual check you did.
