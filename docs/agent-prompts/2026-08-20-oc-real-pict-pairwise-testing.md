## 1. Context

hex-yt-intel is a Next.js/Cloudflare Worker/Supabase YouTube video-intelligence SaaS. This repo has *claimed* pairwise testing since 2026-05-22 (`docs/testing/PAIRWISE_TEST_MATRIX_WAVES_1_4.md`, `.github/workflows/pairwise-test.yml`, 38 documented cases), but investigation tonight (2026-08-20) found this was never real. Specifically:

- The 38 cases in `docs/testing/PAIRWISE_TEST_MATRIX_WAVES_1_4.md` are hand-written and only loosely "pairwise-inspired" — they were never generated by an actual combinatorial-coverage tool.
- `.github/workflows/pairwise-test.yml` has been **disabled since 2026-08-02** (see the `# DISABLED` comment at the top of that file) — it failed every weekly run for a month+ because `tests/pairwise_matrix/` (referenced by the job) was never actually built. Only Phase 1 (spec doc + fixture scaffolding) was ever done.
- The matrix is also stale: 29 of the 38 cases reference NextAuth, which was removed by ADR 001's Supabase-only auth migration (`.memory/ADRS.md` / project `CLAUDE.md` §3).
- Related docs to read for existing scaffolding: `docs/testing/PAIRWISE_TESTING_ROADMAP.md`, `docs/testing/TEST_FIXTURES_IMPLEMENTATION.md`, `tests/fixtures/users.ts`, `tests/fixtures/videos.ts`, `tests/mocks/services.ts` (Phase 1 deliverables, still present, may or may not still be accurate against the current Supabase-only stack — verify, don't assume).

The user asked for this to be fixed properly using Microsoft's real PICT (Pairwise Independent Combinatorial Testing) tool, not another round of hand-written pseudo-pairwise cases. Two real, verified-to-exist candidate integration paths (checked via `gh repo view` tonight, both real and current):
- `github.com/microsoft/pict` — the actual PICT CLI (C++ binary + model-file input format).
- `github.com/ryanrosello-og/pict-pairwise-testing` — a Node.js wrapper around PICT, npm-installable, lower integration friction for a pnpm/TS monorepo than shelling out to a raw binary.
- (`github.com/takeyaqa/PictMCP` also exists — an MCP wrapper — but MCP-based generation is out of scope for a CI pipeline; do not use it here, it belongs to an interactive-agent workflow, not automated CI.)

`microsoft/webwright` (an unrelated agentic browser-automation framework, NOT a pairwise/combinatorial tool) was also raised by the user tonight but is explicitly OUT OF SCOPE for this task — shelved for separate future investigation, not part of this dispatch.
