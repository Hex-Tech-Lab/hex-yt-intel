## Fix, in order, each with a real negative-control test:

1. **P1 useChapters.ts:106 — 4xx treated as retryable**: shared fetch callback returns `{ok:false}` without status, so 4xx enters the same retry/backoff as transient failures. Return discriminated result `{kind:'http-error', status}`; terminate immediately for 4xx (no retry budget spent, no backoff), retry only 5xx/network/timeout/body-failure. Test 401/404 no-retry + 5xx retry.
2. **Gate blocker — useKnowledgeGraph.ts DeepSource complexity** (lines ~109,168,198): `mapGraphPayload` complexity 12, `fetchGraph` complexity 10, unnecessary `let data`. Extract payload validation, node mapping, relation mapping, failure classification into small module-level pure helpers (no behavior change). `let`→`const` where unnecessary. Test each helper.
3. **P2 fetch-with-timeout.test.ts:67-96 — false-confidence negative control**: pre-fix test starts `.json()` only AFTER advancing past the timeout, so it can pass even if the old bug still existed. Fix: start the body-consumption promise BEFORE advancing fake timers, make the mocked response observe the old controller's abort signal, assert it rejects when NOT cleared and stays pending/resolves only when cleared before consumption. Remove unused `oldController`.
4. **P2 useChatStore-resilience.test.ts:76,180 — test isolation leak**: `bindNetwork()` called after the failed send (may flush immediately); failed sends leave real 3s replay timers alive across tests. Register online listener BEFORE creating the failed outbox item, prevent/await immediate flush, use fake timers, clear all scheduled replay timers + remove listeners + reset stores in `afterEach`. Assert fetch count before/after the online event specifically.
5. **P2 fetch-with-timeout.ts:54 — abort listener leak**: caller-signal abort listener never removed after completion. Store the listener reference, remove it in `finally`. Preserve immediate-abort semantics. Test cleanup + all abort paths (success/body-fail/timeout/caller-cancel).
6. **P2 useKnowledgeGraph.ts:109-150 — payload validation too shallow**: only checks `entities`/`relations` are arrays, not that individual items are valid (`{entities:[{}],relations:[]}` passes; `typeof NaN === 'number'` too). Require finite numeric dimensions/weights/strengths, valid string IDs, valid relation endpoints referencing real node IDs — reject the WHOLE payload as retryable if any item is invalid (don't silently drop items). Test null entities, missing IDs, NaN dimensions, invalid relation endpoints, mixed valid/invalid.
7. **P3 useAutoRestoreAnalysis.ts:90,177 — breadcrumb only on header arrival**: emit request-start/failure/success breadcrumbs around the WHOLE fetchWithTimeout call, not just inside consumeResponse — success breadcrumb only after JSON parse+processing completes; pre-header network failures need their own "settled" breadcrumb too.
8. **P2 fetch-with-timeout.test.ts static findings**: unused `oldController` (see #3), async callbacks without `await`, undersized callback param names, global-function-declaration warning — clean without weakening assertions.
