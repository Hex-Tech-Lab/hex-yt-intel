IF [AuthLevel] = "Admin" THEN [APIEndpoint] = "analyses" OR [APIEndpoint] = "metadata";

## 4. How Generated Combinations Map to Test Execution

PICT generates **test input combinations** only (parameter tuples). They must be executed by existing test tooling:

### 4.1 Execution Strategies

#### Strategy A: PICT → JS/TS script → parametrized Playwright tests (RECOMMENDED)

```
model.pict ──PICT──→ 27 combos ──gen-test-cases script──→ Playwright test.each()
```

A small Node.js script reads the PICT model file (via `pict-pairwise-testing` with `textModel` API), wraps the result, and generates Playwright `test.each()` parameters. Each combination becomes a Playwright test with setup logic that configures mocks/services for the given parameter values.

**Estimated effort**: 1-2 sessions (4-6 hours)

Example Playwright structure:
```typescript
// tests/pairwise/generated.spec.ts
import { test, expect } from '@playwright/test';
import { generatePairwiseCases } from './generate';

const testCases = generatePairwiseCases('tests/pairwise/model.pict');

for (const tc of testCases) {
  test(`${tc.Environment} | ${tc.RateTier} | ${tc.ErrorType} | ${tc.CacheState} | ${tc.APIEndpoint} | ${tc.AuthLevel}`, async ({ page }) => {
    // Setup: configure mocks based on tc parameters
    await setupTestEnvironment(page, tc);
    // Execute: call the endpoint under test
    const response = await callEndpoint(page, tc.APIEndpoint);
    // Verify: validate behavior for this combination
    await validateResponse(response, tc);
  });
}
```

#### Strategy B: PICT → JSON file → CI imports generated cases

Run PICT once, commit the JSON output as `tests/pairwise/generated-cases.json`, and import it in Playwright tests. Simpler but the model output becomes stale if the model changes.

#### Strategy C: PICT runs as a pre-test CI step

Add a CI step before Playwright: generate fresh combinations on every run. Cleanest but adds ~100ms to CI.

### 4.2 Fixture/Mock Infrastructure Required

The existing `web/tests/fixtures.ts` provides Playwright test fixtures (authenticated page, stream helpers) but does NOT provide the mock infrastructure described in the old docs (`tests/mocks/services.ts`, `tests/fixtures/users.ts`, etc.).

For PICT-generated tests to execute, at minimum:
- **API mock layer**: Ability to simulate error conditions (NetworkFail, MissingData, InvalidInput) — likely needs MSW mocks or a middleware interceptor
- **Cache state control**: Ability to set Fresh/Stale/Expired cache for Upstash Redis — needs a Redis mock or a test Redis instance
- **Environment detection**: Test needs to know if it's in CI, dev, or production — the `testEnvironments` config from old docs could be revived
- **Auth level simulation**: Ability to run as Public/Protected/Admin — Playwright already has a bypass token mechanism (`X-Hex-Test-Secret`)

**Estimated effort for mock infrastructure**: 1-2 sessions (4-6 hours)

**Total estimated effort (full implementation)**: 3-4 sessions (8-12 hours)

## 9. Tangents Found (Not Fixed)

1. **Dead doc claims**: `PAIRWISE_TESTING_ROADMAP.md` claims "Phase 1 complete, 6 files, 50+ fixtures" — but the fixture files (`tests/fixtures/users.ts`, `tests/mocks/services.ts`, `tests/pairwise/config.ts`) were never created on disk. The only fixture file that exists is `web/tests/fixtures.ts` (Playwright test fixture extensions, not user/video/mock data).
2. **Stale environment expectations**: The disabled CI workflow references `AUTH_PROVIDER: supabase` env var and `DEV_BYPASS_TOKEN` — these may or may not still be the correct auth simulation pattern in the current codebase. Verify before writing the new workflow.
3. **`pict-pairwise-testing` semicolon trap**: The package passes model text verbatim to PICT, including constraints. PICT **requires** `;` at the end of every constraint line. The package's own examples don't mention this, and omitting semicolons fails silently (returns `{ stackTrace, error }`). Any future constraint additions must remember the semicolons.
4. **PICT binary compatibility**: The bundled `pict_nix` binary works on this CI (Ubuntu x64). If the CI runner changes architecture (e.g., ARM64), PICT would need to be compiled from source. Not an issue today.
